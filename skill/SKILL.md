# 个人 Wiki 知识库维护手册

本仓库是一个三层结构的个人知识库。所有内容操作前，先读本文件与 `rules/constitution.md`；**生成任何词条内容前，必读 `rules/style-profile.md`**。

## 三层架构

| 层 | 位置 | 规矩 |
|---|---|---|
| 第 1 层 · 原始资料 | `sources/` | 只读，一个字不改。一切论断的事实来源 |
| 第 2 层 · 词条 | `source/_posts/tech/`、`source/_posts/insights/` | 按词条模板生成，互相链接，每页注明出处 |
| 第 3 层 · 规则 | `skill/rules/` | 本手册 + 组织宪法 + 风格档案 |

Hexo 只渲染 `source/`；`sources/` 与 `skill/` 不出现在网站上，但在 GitHub 仓库中可被链接引用。

## 工作流一：入库（ingest，资料驱动）

用户提供链接 / 文字 / 文件时：

1. 读取 `rules/constitution.md` 与 `rules/style-profile.md`
2. 原始资料存入 `sources/`（全文存档，见 `sources/README.md` 命名与元数据规范）
3. **强制查重**：检索 `source/_posts/` 现有词条，判断操作类型：
   - 新建：全新主题
   - 合并：与已有词条高度重合 → 并入该词条，补充出处
   - 更新：已有词条过时/不完整 → 修订，保留修订痕迹
   - 原则：**能用已有词条承载的内容，不允许新建词条**
4. 按 `rules/constitution.md` 的词条模板写入 `source/_posts/tech/` 或 `source/_posts/insights/`（含 Hexo Frontmatter）
5. 维护"关联词条"双向关系（A 链 B 时检查 B 是否应回链 A）
6. 输出操作摘要：新建/合并/更新了哪些词条

## 工作流二：研究学习（learn，问题驱动）

用户只想了解一个概念、没有现成资料时：

1. **先答**：直接回答问题，标注"⚠️ 此条来自库外，未入库"
2. **再问**：末尾询问"要不要入库？"
3. **再存**：用户确认后，检索收集 2~5 篇真实资料，建立**摘录卡**（不存全文，见 `sources/README.md`），再走工作流一的第 3~6 步生成词条，出处指向摘录卡
4. 词条内容以收集到的真实资料为准，**不直接采用第 1 步的回答文本**

## 工作流三：带规矩问答（ask）

- 优先引用库内词条和 `sources/` 原始资料，引用处标注来源
- 库内没有覆盖的问题，明确说"库里没有相关内容"
- 使用库外知识时，标注"⚠️ 此条来自库外，未入库"

## 工作流四：体检（check）

机械检查（不耗模型 API）：死链、孤儿词条、无出处内容、过期内容。
语义检查（耗 API，默认关闭，用户明确要求才执行）：近义词条识别与合并建议、风格一致性抽查。
合并等破坏性操作只出建议，由用户确认后执行。
